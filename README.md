## Planned programs and usage

Use Python 3.12 or newer from the existing cloud checkout. Task 2 and Task 3 commands are implemented:

```bash
python -m internship.task2 --count 10
python -m internship.task2 --count 0
python -m internship.task2 --benchmark --benchmark-counts 10 100 1000 --repeats 5 --number 100
python -m internship.task3 --root fixtures/task3
python -m internship.task3 --root artifacts/task3/your-synthetic-workspace --apply --csv master.csv
python -m unittest discover -s tests -v
```

`fibonacci(count)` returns exactly `count` terms, beginning `0, 1`. It accepts only non-negative plain integers; `bool`, float, string, and `None` are rejected. The CLI emits a JSON array for a sequence and JSON benchmark data for `--benchmark`; validation errors go to stderr with exit code 2. CLI output is limited to 10,000 terms. Benchmarking uses `timeit` to measure only `fibonacci(count)`, excluding printing, JSON encoding, and metadata collection. It reports sample totals and per-call min/median in seconds, plus Python and platform context. Timings vary by machine and are not performance guarantees.

The iterative algorithm performs O(count) loop steps and stores O(count) terms. Because Python integers have arbitrary precision, additions grow more expensive as Fibonacci values grow; the simplified constant-cost arithmetic assumption does not hold for large counts.

Task 3 requires an explicit existing workspace below `fixtures/task3` or `artifacts/task3`; it rejects other roots, `..` traversal, roots/path components that are symlinks, and symlinked children. Preview may inspect fixtures but changes nothing. `--apply` and CSV writes are allowed only in isolated copies below `artifacts/task3`; canonical fixtures are read-only source material. `--csv` must be a direct `.csv` filename. An existing CSV is rejected unless it is the unchanged master previously generated by Task 3 and authenticated by its `.task3-generated-csv.json` marker, which permits safe regeneration on repeat runs. Validation happens before planning/moving files.

Apply uses collision-safe same-filesystem hard-link/unlink moves, reports partial failures, scans only immediate files plus one organization-directory level, extracts synthetic `.log`/`.txt` records with strict UTF-8, and atomically writes/verifies a UTF-8 CSV. Its fixed columns are `source_path,line_number,kind,value`. CSV cells beginning `=`, `+`, `-`, or `@` are prefixed with an apostrophe to prevent spreadsheet formula interpretation. The regexes target conventional ASCII emails and `TXN-` plus 6–12 uppercase alphanumeric characters; they are deliberately not general email/transaction validators.
